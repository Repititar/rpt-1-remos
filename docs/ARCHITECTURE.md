# RPT-1 Remos — Architecture

RPT-1 Remos is an independently developed, decoder-only Transformer language model by Repititar. The project focuses on building, training, and evaluating a language model from randomly initialized parameters using PyTorch.

## Core Components

### 1. Configuration

**File:** `src/repititar/config.py`

`ModelConfig` defines the model's architecture and numerical settings.

The initial configuration uses:

| Parameter | Default | Description |
|---|---:|---|
| `vocab_size` | 256 | Number of byte-token IDs |
| `d_model` | 256 | Hidden dimension |
| `n_layers` | 6 | Number of Transformer blocks |
| `n_heads` | 8 | Number of attention heads |
| `max_seq_len` | 512 | Maximum context length |
| `dropout` | 0.1 | Dropout probability |
| `rope_theta` | 10000.0 | RoPE frequency base |
| `norm_eps` | 0.00001 | RMSNorm numerical stability constant |

These are baseline settings, not optimized hyperparameters.

### 2. Tokenizer

**File:** `src/repititar/tokenizer.py`

RPT-1 Remos uses a UTF-8 byte-level tokenizer.

- Each byte maps to an integer from 0 to 255.
- Vocabulary size is fixed at 256.
- No vocabulary training is required.
- No pretrained tokenizer is required.
- Decoding converts generated bytes back into UTF-8 text.

The tokenizer is simple and deterministic, but byte-level encoding can require more tokens to represent text than subword tokenization.

### 3. Transformer Model

**File:** `src/repititar/model.py`

The model follows a decoder-only Transformer architecture.

#### Token Embeddings

Maps token IDs into learned vectors of dimension `d_model`.

#### Causal Self-Attention

Computes relationships between token positions while preventing each position from attending to future tokens.

The attention head dimension is calculated as:

```python
head_dim = d_model // n_heads
```

The model requires `d_model` to be divisible by `n_heads`.

#### Rotary Positional Embeddings

RoPE introduces positional information into query and key representations using position-dependent rotations.

#### RMSNorm

Normalizes hidden representations using their root mean square and a learned scale parameter.

#### Feed-Forward Network

The initial design expands the hidden dimension by a factor of four, applies GELU, and projects the result back to `d_model`.

#### Residual Connections

Residual connections combine each sublayer's output with its input to support information flow and gradient propagation.

#### Language Model Head

Projects the final hidden representations into vocabulary logits.

The initial design ties the output projection weights to the input token embedding weights.

### 4. Training

**File:** `src/repititar/train.py`

Training uses causal next-token prediction.

For example:

```text
Input:  A B C D
Target: B C D E
```

The model predicts the next token at each valid sequence position.

The training objective is cross-entropy loss. The initial training design uses AdamW for optimization.

Model parameters are initialized randomly rather than loaded from a pretrained language model.

Training data, optimizer settings, and training duration must be documented for reproducible experiments.

### 5. Generation

**File:** `src/repititar/generate.py`

Generation is autoregressive:

1. Accept an input prompt.
2. Convert the prompt into byte-token IDs.
3. Run the model to obtain vocabulary logits.
4. Apply temperature scaling.
5. Apply optional top-k filtering.
6. Sample the next token.
7. Append the token and repeat.

The model uses a bounded context window based on `max_seq_len`.

Generation quality depends on training data, model parameters, and optimization. The architecture alone does not guarantee coherent or factual output.

### 6. Evaluation

**File:** `src/repititar/evaluate.py`

Evaluation measures next-token prediction performance on held-out text.

The principal metrics are:

- **Cross-entropy loss:** Measures prediction error.
- **Perplexity:** Exponential of the mean cross-entropy loss.
- **Bits per byte:** Cross-entropy expressed in bits per evaluated byte.

Evaluation results should record the model configuration, checkpoint, dataset, device, and number of evaluated tokens.

Comparisons require consistent datasets, tokenization, and evaluation methodology.

## Design Principles

- **From scratch:** Develop the model using randomly initialized parameters.
- **Open research:** Make implementation and research artifacts accessible.
- **Correctness first:** Validate mathematical properties and model behavior before scaling experiments.
- **Reproducibility:** Record datasets, configurations, and training settings.
- **Maintainability:** Keep the implementation modular and readable.
- **Transparency:** Distinguish demonstrated capabilities from planned improvements.

## Development Status

RPT-1 Remos is under active development.

Architecture improvements, training experiments, performance optimization, and model evaluations should be documented as they are implemented and verified.

The project does not claim production-level language understanding or advanced reasoning capabilities without supporting experimental evidence.
